# Clipping Engine private Windows pilot

## Offer in preparation

Clipping Engine helps editors turn footage they have permission to use into short vertical clips. The workflow keeps source provenance, review and publishing approval with the clip. The initial pilot is for a single Windows customer workspace using their own permitted sources and publishing destinations.

An internal Windows installation is operating. The private pilot depends on a clean install on a separate Windows user account, customer credential isolation, a tested recovery procedure and provider approval for external users. The commercial tools are standalone prototypes. Confirm the offer and approved distribution components before providing the build to a customer.

## First-run guide for the pilot

1. Select dedicated config and data folders and validate the workspace descriptor. Assign its own workspace ID and localhost port.
2. Open that workspace's local dashboard. Use a separate Windows login for any external pilot and verify that one workspace cannot read another's files or credentials.
3. Start with a small source file you have permission to edit. Generate one clip, review it, and verify the source and render play. Leave automatic recording and posting disabled during setup.
4. Connect the customer's own supported cloud or publishing accounts after confirming the provider permits the external pilot. Verify the stable destination ID before a test. Publish only after the customer approves the exact clip and destination.
5. Restore a small backed-up clip to a scratch location and compare it with its verified record. Confirm that source retention rules match the customer's agreement.

## Support and exit

Include the installed version, Windows version, available disk, affected page or job ID and the time of the issue in a support report. Leave passwords, access tokens, direct media links and customer footage out of the report unless a separate secure transfer has been arranged.

For an export or exit, agree which clips, original recordings, metadata and approved reports the customer needs. Record which assets are in the local workspace and which are held by cloud or publishing providers. Confirm any retention duties, capture a verified export, revoke provider connections, and verify deletion in the agreed locations. A local workspace change cannot remove content already published at a destination. Test the whole procedure with a synthetic workspace before external onboarding.

## Pilot acceptance evidence

Record the runtime hash, Windows account and hardware profile, clean installation result, first-run capture and review outcome, exact provider consent for external use, backup restore result, failed cross-workspace access checks, and export and deletion results. Preserve approval records for any public test. A private demonstration can use synthetic footage with publishing disabled.
